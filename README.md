# KaneAI playground prototype

A working prototype of KaneAI's agent playground (`design-context/patterns/kane-agent-playground.md`), built from design-context, with mock data only. The first piece is the **session setup state** for a real device app session: what the playground shows from the moment the session opens until the app is on screen.

- **Live:** https://rajat-lt.github.io/kane-playground-prototype/
- **Spec:** [`kane-playground-setup.md`](kane-playground-setup.md) (house format: brief, structure, behaviour, sub-steps, states, illustrations, conflicts, gaps, decisions, copy, open questions; **v2 in §13**)

## Try it

The dashed **Prototype** bar in the top bar is not part of the design. It plays the setup on a clock:

- **Success / Failure** picks the flow and starts it again.
- **Pause** or **Play** holds the clock.
- **Next Step** goes to the next sub-step as it starts, to the moment a long sub-step adds its note, to the moment a step warns, and to the end.
- **Restart** goes back to the first step.

## Run it

```bash
npm install
npm run dev
```

The dev server runs on port 5183. `npm run build` writes `dist/`; `npm run preview` serves it. `npm run tokens` regenerates `src/tokens.css` from design-context's `data/tokens.json` on `main` (the sibling `../design-context` checkout, or `DESIGN_CONTEXT=/path`).

## How it is built from design-context

- **Tokens:** `src/tokens.css`, generated by `scripts/tokens.mjs` (136 tokens, design-context `6cfb737`); each variable names its token path. The device's own colours (its frame, wallpaper and iOS's system colours) are not tokens: they belong to the device (spec §13.8).
- **Components:** look-alikes of `@lambdatestincprivate/lt-components` (private) under their real names, with documented props only (`COMPONENTS.md`): `src/lt.jsx` and `src/overlays.jsx`, carried over from the automation details prototype.
- **Patterns:** `kane-agent-playground.md` (the four zones), `topbar.md` and `platform-sidebar.md` (the shell).
- **Icons:** lucide-react 1.58.0, every name checked in the installed package, on the device too (no Apple icons).
- **Illustrations:** design-context's illustration kit (`illustration-style-kit/skill/lambdatest-illustration`), lifted parts only; see `illustrations/kit-drafts/README.md`.
- **Copy:** `ux-text-guidelines.md`. The device shows iOS's own words, as iOS writes them (spec C20).
- **Product facts:** TestMu AI's KaneAI docs (Advanced Settings, Authoring Session States, iOS App Settings), read 30 Oct 2026 (spec §13.2).

## Files

| File | What it holds |
|---|---|
| `src/App.jsx` | The playground: session bar, step pane with the stage and the composer, device pane |
| `src/setup.jsx` | The setup state: steps and sub-steps, the two flows, the simulated clock, the stage, the announcements and the prototype bar |
| `src/device.jsx` | The device pane: its header and the device, drawn from the setup's clock |
| `src/shell.jsx` | The platform rail and the top bar |
| `src/lt.jsx`, `src/overlays.jsx` | LT component look-alikes |
| `src/styles.css` | Base, shell, primitives and menus (as in the automation prototype), then the playground, the setup stage and the device |
| `src/illustrations/` | The five spots, cut to 120 × 113, each moving piece its own group |
| `illustrations/kit-drafts/` | The spots' kit modules, helpers, cut script and 2x previews, to rebuild them; `kane-failed` is v1's failure spot, unused since v2 |
| `kane-playground-setup.md` | The spec |

## Deploy

GitHub Pages serves the `gh-pages` branch. From a fresh `npx vite build` of `main`: `touch dist/.nojekyll`, commit `dist/` to `gh-pages` and push it.

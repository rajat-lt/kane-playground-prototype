# KaneAI playground prototype

A working prototype of KaneAI's agent playground (`design-context/patterns/kane-agent-playground.md`), built from design-context, with mock data only. The first piece is the **session setup state** for a real device app session: what the playground shows from the moment the session opens until the app is on screen, and when a setup step fails.

- **Live:** https://rajat-lt.github.io/kane-playground-prototype/
- **Spec:** [`kane-playground-setup.md`](kane-playground-setup.md) (house format: brief, structure, behaviour, sub-steps, states, illustrations, conflicts C1 to C11, gaps, decisions, copy, open questions 1 to 10)

## Try it

The dashed **Prototype** bar at the bottom of the page is not part of the design. It plays the setup on a clock:

- **Success / Failure** picks the flow and starts it again.
- **Pause** or **Play** holds the clock.
- **Next Step** goes to the next sub-step as it starts, to the moment a long sub-step adds its note, and to the end.
- **Restart** goes back to the first step.

| Brief item | What to look at |
|---|---|
| 1, 3 | The device pane: a spot, the current main step, its sub-step, then the five main steps |
| 4 | The PM's five steps and their sub-steps (spec §4), with no helper lines; the session bar carries the device and OS |
| 5 | The spot, 120 × 113, a little smaller than the automation setup's 144 × 136 |
| 6 | **Failure**: at *Applying app permissions*, the still failure spot, *App permissions failed to apply*, the failed sub-step with a red cross, the step red in the list |
| 7 | No attempt line; *Installing your app* runs long and adds *Still working on this step. It finishes on its own.* |
| 8 | Three dots after every running sub-step, appearing one by one; a finished sub-step keeps them beside its tick |
| 10, 11 | A looping spot per step: the magnifier searches, the box drops into the phone, the gears turn, the key swings, the rocket bobs in its smoke |
| 12 | Kit drawings moved in CSS, not oil-motion (spec C1, Rajat's answer) |

With the system's reduce motion setting on, the spots, the typing and the shimmer stay still; the dots and the spinner keep going.

## Run it

```bash
npm install
npm run dev
```

The dev server runs on port 5183. `npm run build` writes `dist/`; `npm run preview` serves it. `npm run tokens` regenerates `src/tokens.css` from design-context's `data/tokens.json` on `main` (the sibling `../design-context` checkout, or `DESIGN_CONTEXT=/path`).

## How it is built from design-context

- **Tokens:** `src/tokens.css`, generated by `scripts/tokens.mjs` (135 tokens, design-context `6cfb737`); each variable names its token path.
- **Components:** look-alikes of `@lambdatestincprivate/lt-components` (private) under their real names, with documented props only (`COMPONENTS.md`): `src/lt.jsx` and `src/overlays.jsx`, carried over from the automation details prototype.
- **Patterns:** `kane-agent-playground.md` (the four zones), `topbar.md` and `platform-sidebar.md` (the shell).
- **Icons:** lucide-react 1.58.0, every name checked in the installed package.
- **Illustrations:** design-context's illustration kit (`illustration-style-kit/skill/lambdatest-illustration`), lifted parts only; see `illustrations/kit-drafts/README.md`.
- **Copy:** `ux-text-guidelines.md`.

## Files

| File | What it holds |
|---|---|
| `src/App.jsx` | The playground: session bar, step pane with the composer, device pane |
| `src/setup.jsx` | The setup state: steps and sub-steps, the two flows, the simulated clock, the stage, the announcements and the prototype bar |
| `src/shell.jsx` | The platform rail and the top bar |
| `src/lt.jsx`, `src/overlays.jsx` | LT component look-alikes |
| `src/styles.css` | Base, shell, primitives and menus (as in the automation prototype), then the playground and the setup stage |
| `src/illustrations/` | The six spots, cut to 120 × 113, each moving piece its own group |
| `illustrations/kit-drafts/` | The spots' kit modules, helpers, cut script and 2x previews, to rebuild them |
| `kane-playground-setup.md` | The spec |

## Deploy

GitHub Pages serves the `gh-pages` branch. From a fresh `npx vite build` of `main`: `touch dist/.nojekyll`, commit `dist/` to `gh-pages` and push it.
